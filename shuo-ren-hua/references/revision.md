# 审校：集中修复，再核对原意

审校是写作过程中的一个阶段，不自动要求另一次模型调用。这份文件只安排检查顺序，不另建禁词表。具体规则以各归属文件为准。

## 选择检查范围

短消息或原文清楚的轻度润色，在同一次上下文里核对关键意思、语气与指代即可，不强制读全部参考、保存文件或运行脚本。

解释、教程、分析和一般长文，采用下列一次集中修订。多来源长文或高影响发布增加关键主张的来源核对；独立复核在工具和任务需要时使用，不是依赖前提。

## 一次集中修订

### 1. 任务有没有完成

按 T01 检查问题是否回答、步骤是否可执行、关键要求是否遗漏，形式和语气是否适合当前读者。篇幅不足以完成推导时补必要内容；重复拖慢阅读时合并。不要以字数、材料件数或固定结构判断合格。

叙事看人物眼下目标、视角与场景变化，解释看读者是否能复述关系，工作消息看对方能否知道要做什么。原稿已经合适时按 S02 不改。

### 2. 定位理解障碍

只处理能说明具体原因的卡点：主干埋住、对象不明、关系写错、术语缺少必要解释、同一限定无信息地重复、搭配失准。修法按 L01—L06。

表格、标题、列表或代码后的正文，连同前后内容一起判断。明确名词短语、不歧义的代词、准确长句、必要对比和专业术语可保留。

### 3. 轻改风格

按 S01 处理没有内容的姿态、套话、装饰性重复和不合场合的语气。叙事中已有作用的声音、节奏和留白优先保留。标题、冒号、破折号、清单、排比等不自动构成问题。

不要改完理解障碍后再为了“更像人”重写每句。每处改动需要有助于当前任务。

## 最终保真核对

对实质修改按 F01—F04 复核对象、时间、数字与单位、否定、条件、强度、责任和引用。拆句、换序与前置结论后，重点看限定的作用范围与来源归属是否仍正确。

通读修改后的全文，核对术语和简称、摘要与正文、表格与说明、引用与主张的一致性。这里是文本冷读；没有真实语音工具时不报告“已朗读计时”。

默认到此停止。仍有已定位的重要问题时，允许一次定点修复，并重新核对受影响部分的原意。次数限制不豁免事实错误；无法确认的关键主张应删除、保留不确定性或注明待确认，不能带着已知错误交稿。

## 长文与分块

先尝试同一上下文审校。超出能力时按完整小节分块，给每块提供文档目的、必要术语、关键事实、需保留内容与相邻段落。不要孤立修改一个段落后默认全文成立。

分块后再做一次全文核对，重点看条件是否丢失、叫法是否一致、引用是否错位、表格是否自足、同一边界是否被误合并。不为每块另加多轮普遍润色。

## 可选工具检查

具备本地执行工具且稿件值得检查时，可以运行：

```text
python3 scripts/check_prose.py 稿件.md
```

检查器提供可定位的风险提示与其实现支持的契约核对，不自动改稿。风格 warning/info 不需清零；确定的有效显式契约违例才可作为 error。退出码 0 只表示没有机器确认的 error，不代表全文准确、自然或保真。

是否检查了 Markdown 区域、原稿契约与语义支持关系，以实际报告范围为准。报告未检查、工具不可用或脚本失败时，不能声称“检查通过”。无工具环境按文本规则自查即可。

## 交付

按用户要求交稿。默认只给最终正文，不附内部检查表、规则执行记录或自我评价。用户要求审查报告时，说明关键修改及仍待确认的事项，不把机械检查包装成效果证明。
