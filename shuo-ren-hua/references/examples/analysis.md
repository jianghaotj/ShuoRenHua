# 分析与建议示例

以下均为构造教学示例，不是实际研究或业务结果。运行时只选当前问题相关的 1—2 组。规范定义见 F01/F02、L04/L05。

## A01 结论和必要限定一起出现

- task: 向普通读者解释内测试用反馈。
- audience: 不熟悉评估过程的同事。
- operation: explain_rewrite。
- source_facts: 只观察到一组内部试用反馈，显示部分改善；没有长期效果数据。原文为“考虑到相关长期数据仍存在缺口，不能据此直接对实际效果作确定性评价，现有内部试用反馈显示出部分改善。”
- must_preserve: 内部试用这一来源范围；部分改善；长期效果未知。
- bad_transform: “效果已经很明确，只是还没长期测试。”
- acceptable_outputs: “这组内部试用反馈显示出一些改善。目前没有长期数据，还不能判断改善能否持续。”
- why: 主答案更早出现，同时保留证据强度与长期未知；不得补具体改善率。

## A02 合法对比原样保留

- task: 润色页面指标摘要。
- audience: 产品团队。
- operation: light_edit。
- source_facts: 同一页面访问人数增加、完成率下降；未提供原因分析。原文为“页面的访问人数增加了，但完成率下降了。”
- must_preserve: 同一页面的两个指标及相反变化方向；原因未知。
- bad_transform: “新增访客质量下降，导致页面完成率变低。”
- acceptable_outputs: “页面的访问人数增加了，但完成率下降了。”
- why: 同句对比有用，不为消除对比句而拆散；不能凭两项指标补因果。

## A03 把递进误写修成转折

- task: 修订新版体验总结。
- audience: 产品使用者。
- operation: light_edit。
- source_facts: 新版操作步骤更少，配置仍复杂。原文为“新版步骤更少。不仅如此，配置仍然复杂。”
- must_preserve: 步骤减少与配置复杂两个事实；没有效率或总体满意度结论。
- bad_transform: “新版步骤更少，因此配置更简单，效率明显提高。”
- acceptable_outputs: “新版减少了操作步骤，但配置仍然复杂。”
- why: 修正真实关系，不禁止连接词；不把一步改善扩展到其他属性。

## A04 不同工具的边界不能合并丢失

- task: 压缩两款工具的测试说明。
- audience: 将对比表单独转发给同事的读者。
- operation: summarize。
- source_facts: 甲工具只测试桌面端，乙工具只测试移动端；两项说明都反复写了“不能据此判断其他平台的表现”。
- must_preserve: 甲对应桌面端、乙对应移动端；对未测平台不能作结论；表格单独阅读仍能知道范围。
- bad_transform: “两款工具测试范围有限，表现都不错。”
- acceptable_outputs: “测试范围：甲工具仅覆盖桌面端，乙工具仅覆盖移动端；其他平台的表现尚未测试。”
- why: 可以合并同一阅读单元的共同提醒，不能删掉各对象的实际范围；“表现都不错”没有依据。

## A05 同一主张的重复可以合并

- task: 精简一段试用说明。
- audience: 普通读者，整段一起阅读。
- operation: light_edit。
- source_facts: 原文为“这次结果来自内部试用，仅供参考。内部试用反馈显示部分改善，仅供参考。长期效果仍无数据，仅供参考。”
- must_preserve: 内部试用来源、部分改善、长期数据缺失。
- bad_transform: “试用证明有效。”
- acceptable_outputs: “这次内部试用反馈显示部分改善，但没有长期效果数据。”
- why: 三次笼统提醒可用具体边界取代，限制仍与同一个结论放在一起。
